# LocalGPT 2.9.4 — Role-task benchmark execution

- Workflow prompts now treat the current role task as the authoritative operative instruction. The original user request is background context unless the role task explicitly invokes it.
- Prior Council transcript is labeled as evidence rather than an instruction source, reducing role takeover and topic reset behavior.
- The maintained first-run benchmark team no longer spends an all-member round on readiness-only prose.
- Two Task Curators first prepare one concrete four-task pack with explicit acceptance shapes, using the maintained C# correctness, provider identity, structured settings and accessibility/practical UI categories.
- Every selected Benchmark Subject then executes that exact assigned task pack once, in order, instead of planning the benchmark or re-answering the user's overall request.
- The deterministic LocalGPT calibration engine now runs the full maintained four-task suite at each of the four measured profile points for every benchmark-capable provider-qualified selected member.
- Independent Code Curator, Coverage Auditor, Performance Analyst and Profile Synthesizer roles remain downstream of actual task execution and measurement evidence.
- Council seed version advances to 22 so the corrected maintained benchmark default is restored while previously edited supplied seeds continue to be preserved as user-owned custom copies.
- Wire protocol remains 2.1.1.
