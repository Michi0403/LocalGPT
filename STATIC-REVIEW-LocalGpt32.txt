Implemented
===========
1. Scoped/root-provider diagnostics correction
   - ServiceMethodDiagnosticsRegistration no longer decorates singleton registrations.
   - IDxAiFunctionHandler registrations are excluded because the DX registry and handlers already own invocation/exception logging.
   - Disposable implementations remain DI-owned and are not proxied.
   - IRegexPatternService is a stateless singleton backed by IDbContextFactory-created contexts.
   - Proxy construction and lifetime-selection methods own logged exception boundaries.

2. Adaptive Ollama benchmark
   - localgpt.models.benchmark.autotune is implemented; no NotImplementedException remains in maintained C#/Razor source.
   - Requires fresh human confirmation.
   - Uses only an HTTP(S) loopback Ollama endpoint and only models returned by /api/tags; it never pulls a model.
   - Applies bounded model/profile/task counts and per-call timeouts.
   - Uses deterministic tasks plus an optional task authored by one installed model for its peers.
   - Stops tuning the current model when the next profile improves by less than the configured threshold (default 5 percent), then continues with the next model.
   - Can create a new user-approved CouncilModelPreset and does not overwrite an existing preset.

3. Async continuation policy
   - Maintained C#/Razor source contains zero ConfigureAwait(true) calls.
   - Blazor components use ordinary await so renderer affinity is retained.
   - Context-free services, controllers, persistence, diagnostics and network code use ConfigureAwait(false).
   - await-using disposal remains a reviewed language boundary where changing the local to ConfiguredAsyncDisposable would hide members used by the method.
   - The build guard now performs lexical Python validation and has a reduced PowerShell fallback.

4. Business-object ownership
   - Diagnostics batch state, Council runtime state, DXFunction parameter DTOs, LocalGptCatalog DTOs, persistence state, OneWire secret-file shape, theme state and UI editor/feedback state are under BusinessObjects.
   - No nested class/record/struct/enum declaration remains outside BusinessObjects in maintained C#/Razor source according to the static parser used for this review.

5. Database startup seeding
   - Existing project rows remain database/user authoritative and are tracked as unchanged.
   - Version/revision/requirement/artifact seed operations are additive.
   - A failed concurrency context is cleared and discarded; retry uses a fresh DbContext rather than issuing a second SaveChanges with stale predicates.
