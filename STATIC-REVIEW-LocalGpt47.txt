LocalGPT 2.2.9 static review — source milestone LocalGpt(47)
================================================================

Baseline
--------
- Continued from the uploaded LocalGPT 2.2.7 GitHub Pages Windows ZIP extraction-fix source package.
- Existing PowerShell-created ZIP path handling and GitHub Pages extraction protections were retained.

Implemented scope
-----------------
- Added provider-qualified model identities containing provider kind, provider name, exact endpoint and provider-native model/deployment name.
- Added reusable ProviderModelPanel Razor UI with selection/use, properties, accessible disclosure state, bounded benchmark configuration, cancellation, result details and direct apply.
- Added ProviderModelBenchmarkCouncilPanel for the "all selected models run" workflow and peer review of each successful recommendation.
- Added the reusable model panel to Chat active sessions, Chat Council candidates, Model Council candidates and tested/discovered Install provider models.
- Added mixed-provider Council execution for Ollama, multiple configured Ollama hosts, LM Studio/local OpenAI-compatible providers, OpenAI and Azure OpenAI.
- Preserved same-named models as separate participants by provider endpoint; ambiguous bare model names and stale qualified addresses are not guessed.
- Added safe Council-leader resolution: an ambiguous bare leader name falls back to normal deterministic leader selection.
- Added provider-qualified model fields to OneWire Council routes and hydrated authoritative selections from those routes.
- Added bounded single-model and all-selected benchmark services with deterministic tasks, configurable profiles, early stopping, optional Council review and explicit user-confirmed preset application.
- Benchmark recommendations save provider-qualified routes and retain Ollama num_gpu only for Ollama models.
- Existing legacy bare-name presets remain supported when uniquely resolvable; historical unqualified routes retain legacy Ollama behavior until qualified.
- Configured OpenAI, Azure OpenAI and local OpenAI-compatible credentials are endpoint-bound. A configured local key is not sent to LM Studio or another fallback endpoint.
- Added provider-aware hardware-road normalization and UI so non-Ollama routes never receive or display Ollama-specific GPU-layer settings.
- Application version raised to 2.2.9; WireProtocol package remains 2.1.1 because this patch does not change the public route DTO.

Corrective scope added in 2.2.9
-------------------------------
- Restored text-service ownership for the two new provider-model Razor components.
- Replaced the new provider iterator with a logged materialized list.
- Added the explicit LocalGPT ConfigurationRoot alias and policy-compliant benchmark route identity initialization.
- Removed obsolete MultiModelCouncilService dependencies that generated CS9113 warnings.
- Marked failed final-answer recovery as a failed Council step and stopped failed verifier notices from being presented as peer verification.

Limitations / required owner verification
-----------------------------------------
This environment has no .NET SDK, C# compiler, Windows PowerShell, Windows WebView runtime, DevExpress runtime execution path, live GitHub Actions runner or configured live AI providers. Therefore the archive is intentionally marked UNVERIFIED.

Run at minimum on the intended Windows/.NET environment:

  dotnet restore LocalGPTWebviewWrapper/LocalGPTWebviewWrapper.sln
  dotnet build LocalGPTWebviewWrapper/LocalGPTWebviewWrapper.sln -c Debug
  .\Build-LocalDevelopment.ps1

Then verify in the UI:
- connect Ollama and LM Studio simultaneously, including one identical model name on both endpoints;
- optionally configure OpenAI and/or Azure OpenAI;
- select mixed providers in /chat and /model-council and run one Council;
- run one single-model benchmark and apply its recommendation;
- run Benchmark Council for all selected models and apply the successful recommendations;
- reload the saved preset and confirm provider endpoints remain unchanged;
- confirm a configured local provider API key is not sent to an unrelated fallback endpoint.
