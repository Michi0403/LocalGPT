# LocalGPT 6.0.11 — configurable Council workspace-source review progress

## Why

A completed read-to-EOF SHA-256 curation of uploaded archives does **not** mean a model semantically inspected their source. Previously, a single successful `chat.upload_workspace_file` receipt anywhere in a Council run could satisfy a configured inventory step, even if the step was assigned multiple archives. A missing receipt caused fixed same-step retries regardless of whether the previous retry achieved anything. Ollama's configured tool-turn ceiling could stop a model during a large review without advancing the next goal. A large file-read result may also be truncated for the provider even though its real read cursor advanced.

## Changes

- `CouncilWorkflowStepDefinition` now persists `RequiredCompletedWorkspaceFiles`, `RequireEachWorkspaceArchiveRead`, and `ContinueWorkspaceReviewOnlyOnProgress`. The preexisting configurable retry budget, prompt, strict function policy and optional excerpt injection are retained.
- The non-loop configured workflow executor evaluates actual service-recorded source-read intervals **for that step** before advancing. One full read from the beginning through a final `HasMore=false` result counts as one completed file; duplicate reads and unconnected final pages do not. Multiple progressive calls can form one complete file when the ranges join without gaps. Source snippets supplied by recovery do not earn model read receipts.
- For workspaces containing ZIP archives, an enabled archive-root policy demands at least one completed extracted text/source read per root. Plain-file workspaces have no archive-root quota. The minimum distinct file target is separately configurable; this is *not* a hidden fixed total-file requirement.
- Configured source-review recovery can continue while the model adds genuinely new source coverage (including pages of a large file), but stops on the first retry with no new unique read characters/completed files. An unmet goal stops the gated workflow with a visible warning; it does not report completion or fabricate evidence. The configured maximum remains an absolute bound.
- Both canonical `chat.upload_workspace_file` and Ollama's transport-safe `chat_upload_workspace_file` traces are accepted as registered source-read evidence. Provider-native Ollama tool-result truncation envelopes retain only the registered function's actual read cursor metadata alongside bounded content. DXFunction gateway steps also persist a compact, service-origin cursor receipt independent of a display-truncated JSON body. **Transport-truncated reads do not earn completed-file credit**; distinct truncation attempts may motivate another corrective round with smaller pages, but repeating identical attempts earns no progress. No source contents are written to diagnostic logs.
- `chat.upload_workspace_file` no longer silently inflates caller-requested 1–63,999-character pages to 64,000 characters. The existing database-backed service read bounds still apply; the caller can request smaller pages that actually fit a model's tool-result budget.
- New controls are in the existing DevExpress Council Teams workflow-step editor, with service validation and normalization. These settings round-trip as existing team-definition JSON; there is no new EF table or migration.
- The shipped, resettable Learning Round inventory seed opts into one completed read per uploaded archive root and progress-gated retries (up to eight within the separately configured runtime maximum). Seed version 47 upgrades unmodified system templates while preserving user-owned overrides via the existing seed-copy policy.

## Deliberate boundaries

This release **does not** assert that every one of tens of thousands of extracted files is semantically reviewed in one model turn or that hashing equals understanding. `RequiredCompletedWorkspaceFiles` is the user-selected count; a complete catalog can be curated deterministically while model source review remains incomplete. The rule is attached to configured non-loop source-review steps, not a hardcoded `learning-round` runtime branch. General subjective Council goals still need their own configured objective/completion evidence; model prose alone is not a trustworthy general-purpose completion receipt.

The existing provider turn cap, approvals, cancellation, persistence and architecture guards remain in place. Runtime .NET/PowerShell validation cannot be performed in this non-Windows environment; the full Windows Debug build and a source-review run remain required.
